# POS for Construction Shop — Project Constitution

## Project Overview
A Burmese-language, mobile/tablet-first POS (point of sale) web app for a construction shop, designed for low-literacy and older sales staff. One project folder contains BOTH the sales app (POS) and the admin app (protected routes).

## Tech Stack (non-negotiable)
- React 18 + TypeScript + Vite
- TanStack Query (v5) for API calls, caching, and offline support
- Material UI (MUI) for UI components
- Supabase as backend (Postgres DB + Auth + Storage); photos in the `products` Storage bucket — the DB stores only the image URL, never image bytes
- Agent MUST provide complete Supabase SQL (tables, RLS policies, indexes, seed data) in `supabase/migrations/`
- Offline: product lists & images cached locally (IndexedDB/localStorage via TanStack Query persistence); sales stored offline and synced later
- Install deps: `@tanstack/react-query`, `@tanstack/react-query-persist-client`, `@mui/material`, `@emotion/react`, `@emotion/styled`, `@supabase/supabase-js`, `pwa` (vite-plugin-pwa for offline).

## Sales App (Personnel side) — `/`
1. **Login**: fixed credentials (username + password), verified against Supabase (`users`/`profiles` table or Auth). Session stored; app usable offline after login.
2. **Main Sale Screen**:
   - Large product grid with image + price (MMK), big touch targets (min 64px), minimal text
   - Search box: typing 1–2 words (Burmese or partial) filters products; results shown as tappable cards
   - Tapping a product adds to cart; cart shows item count and running total in MMK with thousand separators (e.g., ၁၂၃,၄၅၀ or 123,450)
3. **Order Summary (checkout):**
   - List of chosen products (image thumbnails, qty +/- controls, remove)
   - Total amount, big and prominent
   - Confirm sale → saves to Supabase `sales` table (or local queue if offline)
   - **Print button** on the summary — abstracted behind a `PrinterService` interface so a Bluetooth printer can be integrated later; for now it can render a printable receipt (window.print) and record `print_requested`
4. **Add Product** (sales staff may also add items): name, price (MMK), image upload/camera capture → goes to same `products` table (with `created_by`)
5. **UI Principles**:
   - ALL user-visible text in Burmese (မြန်မာဘာသာ). No English in UI copy. Burmese-friendly font (e.g., Padauk / Noto Sans Myanmar)
   - Icons + colors + images over text for navigation
   - Very large buttons, high contrast, no small checkbox-like controls
   - Confirmations use big dialogs with large ✅/❌ buttons

## Admin App (protected) — `/admin`
- Protected route: requires admin role (role column in profile) — redirect non-admins to sale screen
- Mobile-first AND usable on desktop (responsive)
- Dashboard: daily, weekly, monthly sales totals + charts (simple visual, MMK)
- Product management: add/edit products (name, price, image)
- No stock/inventory tracking for now (out of scope)

## Database (Supabase) — SQL must be generated by agent
Minimum tables:
- `products(id, name, price_mmk, image_url, is_active, created_by, created_at, updated_at)` with fulltext/ILIKE-friendly search index
- `sales(id, total_mmk, completed_by, created_at, synced_at, status)` 
- `sale_items(id, sale_id, product_id, product_name_snapshot, qty, unit_price_mmk, line_total_mmk)`
- `profiles(id, username, role [sale|admin], full_name, is_active)` / handled via Supabase Auth with fixed seeded users
- All tables need RLS policies. Include seed SQL for fixed credentials & sample products.

## Edge Cases (must be designed for)
- Offline login + offline sale capture; queued sales sync automatically when back online; no duplicate sync (idempotency key)
- Salesperson Searches word with no result → show "မရှိပါ" empty state + "Add new item" shortcut
- Product image missing/broken → placeholder image, never breaks grid
- Price entry errors (0, negative, non-numeric) → block with big Burmese error
- Ded upped item in cart → increments qty, not duplicate line when same product tapped
- Cart with 0 items → print/confirm disabled
- Very large qty / very large totals → maxValue guarding, readable formatting
- Session expiry while selling → local sale still allowed, re-auth prompts after
- Deleting/deactivating a product that exists in an active cart → cart item kept via snapshot
- Network failure mid-sync → retry with backoff, never lose a sale
- Image upload too large / wrong format → compress client-side before upload
- Accidental cart clear → confirm dialog; cart survives app reload (persisted locally)

## Quality Gates (all PRs / implementations must pass)
- `npm run build` and `npm run lint` must pass
- No hardcoded English UI strings — use a constants/labels file in Burmese
- Company look: consistent MMK formatting util used everywhere
- No secrets in code — Supabase URL/anon key via `.env` (`VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`); `.env.example` committed
- Printer + sync behind interfaces so future changes don't break the apps
